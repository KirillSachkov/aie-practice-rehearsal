# Модули помощника

Модули всего помощника, не только первой версии. Версия, в которой модуль начинает работать, указана рядом. Слова из `GLOSSARY.md`, переводы статусов из `language.md`. Контракты с системами компании в `contracts.md`.

## Модули

| Модуль | Скрывает решение | Версия |
| --- | --- | --- |
| **Канал** | как сообщения клиента попадают в помощника и обратно: чат сейчас, Telegram позже; разбор токена входа; когда можно отправлять push и SMS | 1 |
| **Разговор** | как помощник ведёт разговор: языковая модель, правила процессов, лимит расходов на модель, состояние уточнения | 1 |
| **Передача оператору** | как разговор попадает к оператору ровно один раз и с пересказом | 1 |
| **Наблюдение за авариями** | как узнать, что аварию устранили, когда система аварий молчит; обещания об устранении | 1 |
| **Действия клиента** | как выполнить действие, которое меняет деньги, тариф, визит или роутер, ровно один раз и после подтверждения | 2 |
| **Системы компании** | восемь систем: адреса, ключи, таймауты, слой перевода статусов, копия справки | 1 |

Модуль «Системы компании» внутри разбит на адаптеры по системам. Их контракты в `contracts.md`. Слой перевода живёт здесь, остальные модули слов систем не знают.

## Кто чем владеет

| Данные | Владелец | Хранение |
| --- | --- | --- |
| Сообщения разговора, обращения, состояние уточнения, расход на модель | Разговор | 90 дней, потом удаляются |
| Передача: ключ, статус, пересказ, время | Передача оператору | как разговор |
| Обещание об устранении: договор, адрес на момент обещания, авария, срок, статус; последний известный статус аварии по адресу | Наблюдение за авариями | до исполнения или 3 дней, потом 90 дней |
| Исходящие сообщения: канал, текст, «не раньше» | Канал | пока не доставлены, потом 30 дней |
| Журнал действий: ключ, вид, результат, время | Действия клиента | 90 дней |
| Копия справки (статьи и правила тарифов) | Системы компании | обновляется раз в неделю |

Что **не** хранится: тариф, баланс, статус договора, платежи, состояние роутера, визиты. Это источник истины в системах компании, и помощник спрашивает каждый раз, когда решение зависит от значения. Копия допустима для справки: она устаревает не больше чем на неделю, помощник говорит «по справке на дату». Адрес в обещании это значение на момент обещания, им владеет Наблюдение: клиент мог закрыть чат, токена у помощника больше нет.

**Что помнит о клиенте между разговорами.** Только по номеру договора: свои разговоры, передачи, обещания и журнал действий. Помощник не помнит чужие слова клиента как факты о нём («у меня медленный роутер»), каждый раз проверяет в системе.

## Связи

| Откуда | Куда | Вызов или событие | Что несёт |
| --- | --- | --- | --- |
| Канал → Разговор | | событие «Клиент написал» | id сообщения, договор, адрес, текст (повтор по id игнорируется) |
| Разговор → Системы компании | | вызов | запросы по контрактам |
| Разговор → Наблюдение | | вызов «Записать обещание» | договор, адрес, id аварии; ответ: записано / уже есть |
| Разговор → Передача | | вызов «Передать» | id разговора, пересказ; ответ: передано / в очереди / не удалось |
| Разговор → Действия клиента | | вызов «Выполнить» | вид, предмет, подтверждение клиента; ответ: сделано / не сделано / неизвестно |
| Наблюдение → Системы компании | | вызов (опрос) | адрес |
| Наблюдение → Канал | | событие «Авария устранена» | id обещания, договор |
| Системы (хелпдеск) → Передача | | событие «Оператор взял разговор», «Оператор ответил», «Заявка закрыта» | id разговора |
| Передача → Разговор | | событие «Оператор в разговоре» | id разговора: помощник перестаёт отвечать по существу |
| Разговор → Канал | | вызов «Отправить клиенту» | текст, срочность |
| Действия клиента → Системы компании | | вызов | запрос и проверка результата |

Опрос аварий ведёт один модуль, Наблюдение, и по адресу, а не по обещанию: сто человек с одним адресом дают один запрос в 15 минут (ADR 0004).

## Проход по сценарию: аварию устранили ночью, клиент давно закрыл чат

1. 18:10, клиент пишет «Интернет не работает». Канал принимает сообщение, событие «Клиент написал» идёт в Разговор.
2. Разговор через Системы спрашивает аварии по адресу, получает «авария действует, срока нет».
3. Разговор вызывает Наблюдение «Записать обещание». Наблюдение записывает обещание (адрес, авария, срок до 3 дней).
4. Разговор говорит клиенту: «Напишу, когда устранят». Клиент закрывает чат.
5. Наблюдение каждые 15 минут спрашивает аварии по адресу через Системы.
6. 02:20: авария устранена. Наблюдение помечает обещание выполненным и публикует «Авария устранена».
7. Канал получает событие, кладёт сообщение в чат сразу, а push записывает с «не раньше 09:00» (ночью уведомления не уходят).
8. 09:00 Канал отправляет push. SMS не отправляется.
9. Клиент открывает чат: «Нет интернета». Разговор продолжается с тем же id.
10. Разговор вызывает Передачу. Передача проверяет, есть ли уже передача для этого разговора. Нет: создаёт запись «отправляется», вызывает хелпдеск.
11. Хелпдеск принял разговор, ответ не дошёл. Передача читает статус разговора в хелпдеске, видит «передан» и помечает запись переданной. Повторной передачи нет.
12. Клиент пишет снова «Ну что там?». Разговор видит, что передача есть, отвечает «оператор ответит» и вторую передачу не вызывает.

Что будет, если следующий шаг не случится: если шаг 7 не случился, сообщение остаётся в исходящих, Канал повторит; если шаг 10 упал на записи, повтор создаёт ту же запись по ключу разговора.

Проверка на лишние модули: каждый модуль участвует в этом или других сценариях `processes.md`. Действия клиента впервые нужны в версии 2 (перезагрузка роутера), в первой версии их нет.

## Открытые вопросы

- Срок хранения 90 дней выбран владельцем, у компании требований к хранению нет: вопрос к компании.
- Как Канал отличает «клиент закрыл чат» от «чат открыт»: зависит от кабинета и приложения компании; в версии 1 всегда пишем и в чат, и push.
