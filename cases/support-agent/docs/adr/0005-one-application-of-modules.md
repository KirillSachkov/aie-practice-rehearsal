# 0005. Помощник это одно приложение из модулей

## Контекст

Помощника развивает небольшая команда. Шесть модулей (`modules.md`) выпускаются вместе, Наблюдение за авариями и Канал связаны событиями, которые должны записываться в одной транзакции с данными модуля. Данные карт, кроме этого, не проходят через помощника: ни одной причины выделять сервис из списка (другая нагрузка, чувствительные данные, своя команда, независимый сбой) нет. Нагрузку во время аварии сглаживают лимиты и один опрос по адресу (сценарий 2 в `qualities.md`).

## Решение

Одно приложение, внутри разделённое на модули, с одной базой данных; у каждого модуля свои таблицы, чужие таблицы он не читает (ADR 0003). Приложение запускается в двух режимах из одного кода: обслуживание чата и фоновые задачи (опрос аварий, отправка исходящих сообщений).

## Рассмотренные варианты

- Сервис на каждый модуль. Отклонён: команде пришлось бы поддерживать сеть и деплой для шести сервисов, а причин нет.
- Отдельный сервис для опроса аварий. Отклонён сейчас: нагрузка мала (один запрос в 15 минут на адрес). Вернёмся, если адресов с обещаниями станет тысячи.
- Один модуль без границ. Отклонён: изменения Передачи затронули бы Разговор и Наблюдение.

## Последствия

Опрос и отправку можно вынести в отдельный сервис, потому что модули общаются только через контракты. Telegram добавляется модулем Канал.
